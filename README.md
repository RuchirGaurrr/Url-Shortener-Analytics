# URL Shortener with Analytics

A production-ready, backend-heavy REST API built with Django and Django REST Framework. Shortens URLs with domain-aware slugs, tracks click analytics in real time, and uses Redis for high-performance caching and rate limiting.

**Live API:** https://url-shortener-analytics-962g.onrender.com  
**Admin Dashboard:** https://url-shortener-analytics-962g.onrender.com/admin/

---

## Features

- **URL Shortening** — Generate short URLs with domain-aware slugs (e.g. `youtube-xK9m`)
- **Custom Slugs** — Users can optionally provide their own slug
- **Redis Caching** — Cache-aside pattern for O(1) redirect lookups
- **Click Tracking** — Logs device, browser, country, and timestamp on every redirect
- **Analytics API** — Query click stats per URL (by device, browser, country)
- **JWT Authentication** — Stateless auth with access + refresh tokens
- **Rate Limiting** — Redis-based counter limiting users to 20 URLs/day
- **Django Admin** — Full admin dashboard for managing URLs and click data
- **20 Unit Tests** — Full test coverage across all apps

## Architecture

```
Client (Postman / Browser)
        ↓
Django + DRF (REST API)
        ↓
┌───────────────┬──────────────┐
│  PostgreSQL   │    Redis     │
│  (Primary DB) │  (Cache +    │
│               │   Rate Limit)│
└───────────────┴──────────────┘
```

**Pattern:** Client-Server with REST API  
**Storage Strategy:** Two-tier — PostgreSQL as source of truth, Redis as cache-aside layer  
**Auth:** Stateless JWT via djangorestframework-simplejwt

## API Endpoints

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| POST | `/api/auth/register/` | No | Register new user |
| POST | `/api/auth/login/` | No | Login, get JWT tokens |
| POST | `/api/auth/refresh/` | No | Refresh access token |
| POST | `/api/auth/logout/` | Yes | Logout, blacklist token |
| POST | `/api/urls/` | Yes | Create short URL |
| GET | `/api/urls/` | Yes | List user's short URLs |
| DELETE | `/api/urls/<id>/` | Yes | Delete short URL |
| GET | `/<slug>/` | No | Redirect to original URL |
| GET | `/api/analytics/<slug>/` | Yes | Get click analytics |

## Key Design Decisions

**Cache-Aside Pattern with Redis**  
Every redirect checks Redis first. On cache miss, PostgreSQL is queried and the result cached for 24 hours. This means only the first visit to any short URL hits the database — subsequent visits are served from Redis in microseconds.

**Domain-Aware Slug Generation**  
Slugs are generated by extracting the source domain prefix and appending a random suffix (e.g. `youtube-xK9m`). This makes shortened URLs more recognizable and trustworthy compared to purely random slugs.

**Denormalized Click Count**  
`click_count` is stored directly on the `ShortURL` model for O(1) total count lookups, while individual `Click` records store full analytics data. This avoids expensive COUNT queries on high-traffic URLs.

**Redis-Based Rate Limiting**  
Rate limiting uses atomic Redis INCR operations with 24-hour expiry — making it thread-safe across multiple Django workers and stateless by design.

## Local Setup

```bash
# Clone the repo
git clone https://github.com/RuchirGaurrr/Url-Shortener-Analytics.git
cd Url-Shortener-Analytics

# Create virtual environment
python -m venv env
env\Scripts\activate  # Windows
source env/bin/activate  # Mac/Linux

# Install dependencies
pip install -r requirements.txt

# Create .env file
cp .env.example .env
# Fill in your PostgreSQL and Redis credentials

# Run migrations
python manage.py migrate

# Create superuser
python manage.py createsuperuser

# Run server
python manage.py runserver
```

## Interview Talking Points

1. **Cache-aside pattern** — Redis caching for O(1) redirect lookups
2. **Two-tier storage** — PostgreSQL for persistence, Redis for speed
3. **Stateless JWT auth** — scales horizontally across multiple servers
4. **Atomic rate limiting** — Redis INCR for thread-safe counters
5. **Denormalized analytics** — click_count on model + Click records for detail
6. **Domain-aware slugs** — custom slug generation with domain prefix extraction
7. **Separation of concerns** — three Django apps each with single responsibility
8. **N+1 query prevention** — select_related in admin querysets
